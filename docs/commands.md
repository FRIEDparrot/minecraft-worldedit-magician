# Command Reference

> The complete inventory of every command the mod exposes. Generated by reading `WorldeditMagicianClient.kt`, `AgentFlow.kt`, `AgentStepPlan.kt`, `MinecraftCommandWhitelist.kt`, `ChunkSelectionCommandGuard.kt`, and every related store/screen.

Conventions:

- `…` means "more arguments of the same shape"
- `[arg]` is optional
- `<arg>` is required
- All commands are **client-side**; no operator permission required to type
- `[WEMC]` prefix is added by the mod when it prints to chat — don't type it

---

## `/wemc …` — Top-level entry points

| Command | What it does | Side effects |
|---|---|---|
| `/wemc` | Open settings panel | none |
| `/wemc config` | Open settings panel (`WemcConfigPanelScreen`) | none |

## `/wemc status` — Status & mode

| Command | What it does |
|---|---|
| `/wemc status` | One-line summary: agent name, `provider:model`, reasoning effort, context window, max output tokens, approval mode |
| `/wemc operation single` | Set agent mode = `SINGLE` (cancels any active flow) |
| `/wemc operation flow` | Set agent mode = `FLOW` (default) |
| `/wemc operation status` | Show operation mode + the four numeric limits |
| `/wemc approval ask` | Approval mode = `ASK` (queue + manual run) |
| `/wemc approval approve` | Approval mode = `APPROVE` (auto-run) |

---

## `/wemc provider …` — AI provider

| Command | Effect |
|---|---|
| `/wemc provider list` | Print every `AiProvider` with `[active, ]configured` / `needs configuration` |
| `/wemc provider use <id>` | Switch active provider. **Restores the saved model for that provider; never falls back to another provider's model.** |

Provider ids: `openai`, `ollama`, `claude`, `gemini`, `deepseek`, `minimax`, `minimax_cn`, `xai`, `mistral`, `cohere`, `perplexity`, `azure`, `custom`, `copilot`.

---

## `/wemc model …` — AI model

| Command | Effect |
|---|---|
| `/wemc model list` | Fetch the active provider's model catalog from its API and print it |
| `/wemc model use <provider:model>` | Pick a model. The argument is one token `provider:model`; quote it if the model id contains spaces (e.g. `azure:my deployment`). |

## `/wemc chat …` — Send a prompt

```
/wemc chat <prompt…>
```

- **SINGLE mode**: exactly one AI request; reply must contain one multi-line `wcl` program, which goes through compilation, approval, and execution. No automatic continuation.
- **FLOW mode**: starts a bounded multi-step flow. The agent declares `steps:` in a `wemc-plan` block; you approve with `/wemc flow approve`; commands auto-execute; the controller feeds server responses back to the agent up to `maxAiRequests` × 30.

The agent's reply always includes a `Player state:` block (position, rotation, looking-at block, current chunk, selection mode, Y range, selected-chunk count) plus the current whitelist.

## `/wemc command …` — Whitelist & history

| Command | Effect |
|---|---|
| `/wemc command list` | List page 1 of the whitelist (10 per page, ordered as in §6 of `documentation.md`) |
| `/wemc command list <n>` | Jump to page `n` |
| `/wemc command history` | Print every command WEMC has **actually sent** to the server this session, newest first (`ExecutedCommandHistory.entries`, capacity 100) |
| `/wemc command wcl-history` | Print generated WCL source and compiled MC command count (up to 20 entries), newest first |

## `/wemc agent …` — Approval queue

| Command | Effect |
|---|---|
| `/wemc agent commands` | Print the whitelist plus, if a batch is queued, the commands pending approval |
| `/wemc agent run` | Send the pending batch through the executor now. Clears the queue. |
| `/wemc agent discard` | Drop the pending batch. Clears the queue. |

The pending batch is populated from compiled WCL output when approval mode is `ASK`. In `APPROVE` mode the queue is always empty after each reply.

## `/wemc query …` — Vanilla-syntax hints

These are **help messages**, not query implementations.

| Command | Hint printed |
|---|---|
| `/wemc query time` | `Vanilla time query syntax: /time query <daytime\|gametime\|day>. Use /wemc command list to see agent-enabled commands.` |
| `/wemc query entity` | `Vanilla Java Edition has no /entity query command. Use /data get entity <single-target> [path] through an enabled Query command.` |

> The query handlers `TimeQueryHandler.query()` and `EntityQueryHandler.query()` exist in the source but are not wired to these literals. If you want to read world time or list nearby entities, run the vanilla commands directly.

## `/wemc flow …` — FLOW-mode controls

| Command | Effect |
|---|---|
| `/wemc flow approve` | Accept the agent's `wemc-plan`. If the plan included step 1's commands, they execute immediately. Otherwise the controller prompts the agent for step 1. |
| `/wemc flow cancel` | Abort the active flow (no-op if none is running). |
| `/wemc flow status` | Show whether a flow is active. |

> `/wemc flow cancel` when no flow is active prints `No active flow.` and does not error.

## In-game (no chat) commands

These are **keybindings**, not chat commands.

| Default key | Effect | Notes |
|---|---|---|
| `O` | Open `/wemc` settings panel | Only fires when no screen is open |
| `Ctrl + C` (with torch in main hand) | Cycle operation mode: `REPLACE` → `ADD` → `REMOVE` | Discards draft |
| `Ctrl + V` (with torch in main hand) | Toggle shape: `SINGLE` ↔ `AREA` | Discards draft |
| `Delete` (with torch + Ctrl) | Cancel current draft only | |
| `Ctrl + Shift + Delete` | Cancel draft **and** clear all confirmed chunks | |
| `Ctrl + Mouse Wheel` (with torch in main hand) | Shift the entire Y range up/down by 1 block | |
| `Ctrl + Shift + Mouse Wheel` | Adjust upper Y bound | |
| `Ctrl + Alt + Mouse Wheel` | Adjust lower Y bound | |
| (no key) Mouse Wheel while in AREA mode and a draft is in progress | Move corner 2 one chunk in the direction the player faces | |

Mouse interactions:

| Input | Effect |
|---|---|
| Ctrl + left-click on a block (with torch in main hand) | Stage its chunk for selection. Initializes the Y range if not already configured. |
| Right-click on a block (with torch in main hand) | Confirm the orange draft → it becomes the confirmed selection. |

## What the mod will **never** accept

These look like Minecraft commands but are explicitly rejected by the whitelist:

| Root | Rejection reason |
|---|---|
| `/execute …` | "`execute` is not allowed because it can bypass WEMC command and chunk-selection safeguards." |
| `/teleport …` | "Use the Flow context form /tp @s ~ ~ ~; /teleport is not enabled." |
| `/tp <other>` | Validator only matches the exact form `tp @s ~ ~ ~` for Flow position context |
| `/function …`, `/schedule …`, any command-block root, any admin/server-lifecycle root | `'<root>' is not on the WEMC command whitelist.` |
| `/clear … 0` | Belongs to the **Query** category (read-only inventory count). To actually clear, use the Inventory form (any trailing integer except `0`). |
